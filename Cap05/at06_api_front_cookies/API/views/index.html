API Amigo do Pet

Documentação Completa do Sistema CRUD Dinâmico Autenticado

Autenticação

Acesso Método Endpoint Descrição
Pública POST /login Valida credenciais do usuário e retorna o Token JWT necessário para as rotas protegidas.

Exemplo JSON - Endpoint de Login

{
  "email": "leo@email.com",
  "senha": "123"
}

Como usar o Token?

Ao fazer o login com sucesso, a API retornará um JSON contendo a propriedade token. Copie esse token.

Para acessar as rotas protegidas das outras abas, adicione um Header na sua requisição HTTP com a seguinte estrutura:


Authorization: Bearer [COLE_O_TOKEN_AQUI]

Gestão de Usuários

Acesso Método Endpoint Descrição
PúblicaPOST/usuariosCadastra um novo usuário no banco de dados.
ProtegidaGET/usuariosLista todos os registros da tabela usuarios.
ProtegidaGET/usuarios/1Busca um usuário específico pela Chave Primária.
ProtegidaPUT/usuarios/1Atualiza dados dinamicamente usando o ID.
ProtegidaDELETE/usuarios/1Remove o registro permanentemente.

Exemplo JSON Completo (POST /usuarios)

{
  "nome": "Leonardo Fernandes",
  "cpf": "12345678901",
  "telefone": "17999999999",
  "whatsapp": "17988888888",
  "email": "leo@email.com",
  "senha": "senha_segura_123"
}

Exemplo JSON - PUT Atualizar (Protegido)

// Requer no Header:
Authorization: Bearer seu_token_jwt_aqui
{
  "nome": "Leonardo Fernandes Atualizado",
  "telefone": "17888888888"
}

Regras de Negócio

  • O nome, cpf, email e senha são campos obrigatórios (`NOT NULL`).
  • O cpf deve ter exatamente 11 caracteres.
  • email e cpf são campos únicos (`UNIQUE`).
  • A senha é automaticamente encriptada no cadastro pelo Controller.
  • Excluir um usuário (`DELETE`) remove em cascata seus pets devido à constraint `ON DELETE CASCADE`.

Gestão de Animais

Acesso Método Endpoint Descrição
PúblicaGET/petsRetorna a lista completa de animais disponíveis.
ProtegidaPOST/petsVincula um novo pet a um usuário existente.
ProtegidaGET/pets/10Busca detalhes de um animal específico pelo ID.
ProtegidaPUT/pets/10Atualiza informações do pet.
ProtegidaDELETE/pets/10Exclui o animal do sistema.

Exemplo JSON Completo (POST /pets)

// Requer no Header:
Authorization: Bearer seu_token_jwt_aqui
{
  "id_cli": 1,
  "nome": "Rex",
  "sexo": "M",
  "especie": "Cachorro",
  "raca": "Labrador",
  "peso": 25.50,
  "tamanho": "Grande",
  "idade": 3,
  "doenca": "Nenhuma",
  "obs": "Dócil, vacinado e vermifugado"
}

Dicas de Integração e Estrutura

A listagem geral GET /pets é pública para permitir que visitantes vejam a vitrine de adoção. Porém, para alterar dados, é obrigatório estar autenticado.

Constraints:

  • O id_cli é uma Chave Estrangeira. O usuário (dono) precisa existir na tabela de usuários.
  • O sexo aceita apenas 'M' ou 'F'.
  • Os campos nome e especie são obrigatórios.

Gestão de Doações

Acesso Método Endpoint Descrição
ProtegidaPOST/doacoesRegistra uma nova intenção de adoção.
ProtegidaGET/doacoesConsulta o histórico de todas as doações.
ProtegidaGET/doacoes/5Consulta os dados de um processo de doação específico.
ProtegidaPUT/doacoes/5Finaliza a doação ou altera o status (ex: Aguardando -> Concluído).
ProtegidaDELETE/doacoes/5Cancela ou remove o registro de doação.

Exemplo JSON Completo (POST /doacoes)

// Requer no Header:
Authorization: Bearer seu_token_jwt_aqui
{
  "id_pet": 10,
  "id_cli_interesse": 2,
  "data_interesse": "2026-05-28",
  "data_doacao": null,
  "status": "Interessado"
}

Exemplo JSON (PUT - Finalizar Doação)

// Requer no Header:
Authorization: Bearer seu_token_jwt_aqui
{
  "data_doacao": "2026-06-02",
  "status": "Concluída"
}

Regras do Fluxo de Doação

Todas as rotas de doação são protegidas, garantindo que apenas usuários registrados possam participar de processos de adoção.

Relacionamentos:

  • O id_pet garante que o processo se refira a um animal válido. Se o pet for deletado, a doação é apagada em cascata.
  • O id_cli_interesse vincula o possível adotante. Se esse adotante apagar a conta, o campo na doação vira NULL, mas o histórico da doação do pet não é perdido (`ON DELETE SET NULL`).
